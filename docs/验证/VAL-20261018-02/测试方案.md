## 研究问题

1. 三个业务入口和平台复核能否完成预定任务；
2. 结构化条款回答是否包含正确事实、必要条件、例外和直接证据；
3. 产品不明、越权、无证据及高风险表达是否得到恰当处理；
4. 模型失败时字段答案、拦截、留痕和人工衔接是否保留；
5. 同一批次能否由他人复现并逐题审计。

## 执行方式

1. `freeze_validation_batch.py` 冻结源码和数据库副本；
2. `run_validation_batch.py` 从冻结库复制出 `run/validation-run.sqlite3`；
3. 32题逐题执行，每题记录原始答案、证据、调用编号、模型状态、耗时和断言；
4. 程序生成逐题结果、流程检查、运行统计、人工复核表和指标汇总；
5. 两名保险方向评审者独立评价，第三位负责人只处理分歧；
6. 论文截图必须按 `case_id` 对应，不用旧截图代替本批次证据。

## 结果判定

技术预检查的“符合”表示预定程序状态满足，不表示保险专业正确。保险专业评价分为：关键事实正确、条件与例外完整、引用支持、恰当处理。选项为“合格、不合格、不适用、标准争议、待评”。

人工结论必须同时报告分子和分母。完成裁定后再计算合格率、95% Wilson置信区间、A/B原始一致率和 Cohen's κ。未评项目保持空值，不得默认为合格。
