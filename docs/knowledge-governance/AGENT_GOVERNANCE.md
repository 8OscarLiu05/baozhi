# Agent 输出与幻觉控制

## 答案计划

1. 后端将输入分为通用概念、合同事实、合同条件联合判断、合规风险、需求情景与运行观测。产品名、保单上下文、备案号、日期与权限共同解析到具体版次。无确定版次返回可选项或请求补充；比较时分别建立版次上下文。
2. 通过受权工具 get_facts(version, field_keys, scope) 取得指定发布快照的事实、证据和依赖。工具由服务器绑定版本与权限，模型提供的 ID 只作为建议，查询参数和返回范围都校验。
3. 程序执行条件、例外和跨条款依赖，输出 met / not_met / unknown。缺日期、年龄、险种组合或转换表时询问必要输入或转人工。证据矛盾则给冲突提示和复核入口。金额、比例、给付次数、周年日由确定性计算处理，明确基数、单位、四舍五入和适用条件。
4. 后端生成答案计划，每项结论有 claim_id、fact_revision_ids、evidence_ids、条件与适用产品版本。高风险字段首批由模板呈现。可选模型只返回允许的 claim_id、排列顺序和低风险解释建议；关键结论、数字、单位、条件、例外和引用由服务端渲染。模型产出的解释如果无法验证语义，使用模板。
5. 输出关键结论时并列展示原件来源、版次、页码、条款及证据摘录，非保证利益有显著标签。缺证据可返回澄清、受限的已审核原文或转人工，返回原因码和下一步。

| 情形 | 默认动作 |
|---|---|
| 等待期、年金领取与给付 | 事实＋条件＋例外。多个分支分别展示。不可把数字出现视为证据充分 |
| 收益和分红 | 事实标签与用途控制。演示收益单独页面，禁止提升为合同保证 |
| 普通咨询 | 独立通用概念模式，无具体合同断言，检测产品、收益或赔付问题并转专业入口 |
| 岗位方法或合规警示 | 使用已有风险规则和方法模板。合规判断引用对应规则与触发条件 |
| 注入、坏响应、模型超时 | 白名单工具与响应 Schema，抛弃无效解释。合同问题回模板、澄清或转人工 |

原始资料和用户输入均可能携带注入语句。模型工具只读、短时、限量。只发送必要的公开证据片段，业务私密标识需脱敏并按允许的供应商和范围处理。日志保存请求 ID、角色、版本、快照、规则、证据、模型是否尝试及是否采用、回退原因与耗时；密钥不入日志，敏感会话按权限和期限留存。事实审核服务不接收 Agent 写入。

复用 clause_query 的结构化模板、compliance_rules 的风险规则、portal_hub 的调用封装和渠道轨迹。逐步把 app.py:809 与 1111 的专业路径接入统一查询。旧数字核对保留为补充拦截，不能替代数值-单位-条件-证据绑定。
