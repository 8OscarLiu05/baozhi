# 前端升级计划

沿用平台工作台的「资料与版本」「事实与出处」「来源处理」和两版原生脚本。现有入口、路由参数、历史调用/抽检、产品与设计功能保持可用。通过新增功能开关与现有知识页并行部署。先接国内版试点，再验证国际版状态、权限及语言一致性。

| 区域 | 现有接点 | 新交互及数据 |
|---|---|---|
| 产品及合同版本 | 两套 app.js 的 knowledgePage、lifeTablesHtml | 公司、备案号、日期、当前发布、主附险关系、旧资料标识、版次冲突提示 |
| 批量资料及任务 | showDoc、资料页 | 批量上传、分条来源确认和文件状态。任务详情显示阶段、页数、异常、失败重试。服务端轮询为首选 |
| 事实审核 | 原文对照视图 | 左侧事实与条件，右侧 PDF 页、条款和表格锚点。支持修订、驳回、通过、差异对比、待补证据，确认包含精确 revision |
| 错误统计 | 现有平台抽检旁新增入口 | 按任务、材料、版次、风险、错误码和审核状态筛选，区分抽取错误与渠道答复错误 |
| 发布与版本 | 现有演示发布面板旁独立正式发布页 | 查看变更、阻塞、审批、发布人、发布时间与回滚。历史快照和调用引用可点回原记录 |
| 展业、客户、电话 | channelPage、证据卡 | 维持 reply/evidence/trace 展示。增版次、证据定位、非保证标签、澄清、回退和转人工 |
| 国际版 | static/app.js 及 intl.py | 复用同一 API 和字段标识，翻译状态文本与通用模板；合同原文按原语言保存并区分译文 |

建议 API 前缀 /api/knowledge/v1。GET /products/{id}/versions、GET /materials、POST /uploads、GET /jobs/{id}、POST /jobs/{id}/retry、GET /reviews?status=pending、POST /facts/{id}/review、POST /versions/{id}/releases、POST /releases/{id}/restore。提交审核或发布前带 expectedRevision / expectedHead，陈旧界面收到 409 后显示差异。二进制原文仅提供受权读取，前端转义引文及外部元数据，禁止拼接不受信任 HTML。上传、重试、审核与发布使用各自角色，服务端拒绝越权。

验收包含旧入口深链、窄屏键盘访问、切换语言、失去权限、超时、重复上传、失败重试、陈旧审批、防注入和业务端不显示待审核事实。先沿用现有双脚本和 CSS；共用接口映射和状态定义，减少语义漂移。
